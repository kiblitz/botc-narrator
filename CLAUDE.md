# botc-narrator: agent context

Rust Blood on the Clocktower storyteller engine. Read README.md for the architecture.

## Decisions (do not revisit without the user)

- Rewritten from OCaml to Rust (2026-10-20). The OCaml free monad was replaced by ability contexts (`ctx::Read` / `ctx::Write`) passed to plain functions; the read/write split replaces the phantom permission types.
- Storyteller discretion goes through `storyteller::Decision` with only legal options and a typed reason. The AI storyteller is an LLM CLI with the prompt on stdin, never an API: `storyteller::claude` (`claude -p`) for the console demo, and the web app's bridge runs `codex exec` (configurable) with the same prompt and parser. Tests use `storyteller::Scripted`.
- Info abilities supply truthful and misinformation options; poisoning is handled centrally by `ctx::Read::inform`, never per character.
- Grimoire status is reminder tokens (`game::Reminder`), not per-effect boolean fields.
- The simulator (`src/sim.rs` -> `web/` wasm -> `site/`) records every step with an audience (public / player / storyteller) and a grimoire snapshot; the table gets the grimoire with each event (`table::Io::event`), so every grimoire change must go through `ctx::Write::record`. In a player's view the site shows only that player's knowledge, and night deaths are announced at dawn without their cause.
- Character icons are the official art, hotlinked from the townsquare (clocktower.online) repo pinned to a commit in `site/app.js`; never copy them into this repository.
- Scripts are registered in one place, `script::all()` (from `script::SCRIPTS`); the simulator's Script picker lists whatever is there.
- No GitHub Actions. `scripts/check.sh` is the merge gate.
- Scripts are data: `data/scripts/<id>.json` (official ids, matched to `Def::id` ignoring underscores) through the `characters::all()` registry, listed in `script::SCRIPTS`. Night orders are computed from each character's `night_order` (clocktower.online numbering), never hand-written.
- Information abilities learn about other players only through registration (`ctx::Read::registers_evil` / `registered_character` / `registers_as`), so misregistration (Recluse, Spy) is central; the storyteller decides each query.
- A player who believes they are a character they are not (`Player::believes`) acts as it but is malfunctioning. Hooks run for every ability a player has (`State::abilities`: own unless lost, believed, gained).
- Any death (demon, execution, ability) goes through `ctx::Write::kill`, where abilities may prevent or redirect it (`intercept_death`). Setup counts come from `setup_counts` adjustments applied by `setup::choose`.

- Fabled and Loric (Knaves, Storm Catcher are Loric per the wiki) are storyteller-side `character::Kind`s: every one listed on a script is in play; they act through the `fabled_*` hooks, which take no player. Travellers are seated at setup with a chosen alignment (`game::Seat::traveller`); the simulator adds up to two when the script lists Travellers.

- Adding a character is one file `src/characters/<id>.rs` plus one `registry!` line, with no engine edits: compose `ability` building blocks; if a character family needs engine support, add a general mechanism (generic `storyteller::Reason::Ability`, `info::Message` variants), never a special case. Guide: `docs/adding-characters.md`.

- Multiplayer web app (2026-10-21, user: "do it"): `server/` (botc.kiblitz.xyz on slot1, port 8081) + `bridge/` + `server/static/`; docs/webapp.md. The host is a player, never the narrator; the storyteller is the engine plus a bridge running Codex (`codex exec`, configurable) on someone's PC, falling back to `storyteller::Random` so a game never stalls. Nobody signs in (user, 2026-10-21): anyone hosts anonymously (the host's seat token on their phone makes them host), capped at 3 rooms per client address, lobbies expire after an hour; joining is by room code. The bridge is run from a one-line command on the host's screen (`curl …/bridge.sh | sh -s -- CODE` or PowerShell `irm …/bridge.ps1`), which fetches `server/static/bridge.mjs` and runs it with Node; it auto-detects codex then claude, `--codex-home` picks a Codex login; the Rust `bridge/` stays as an alternative and owns the wire protocol (user, 2026-10-21). Rooms are in memory. Sockets authenticate in their first message, never the URL. Bridge pairing codes are host-only (the bridge sees the grimoire).
- The host runs every nomination and vote (user, 2026-10-22, against misclicks): the host's phone picks nominator, nominee (legal choices only), confirms or cancels, then taps each raised hand round the circle and closes the vote (no timeout). The server rejects `nominate` / `vote` / `close_vote` from any other phone; other phones only watch the vote. Exception: the Butcher picks their second nominee on their own phone (an ability prompt). Storyteller (Bishop) and Butcher nominations are voted the same way.

- Public day abilities can be bluffed (user, 2026-10-22): a day ability used in front of everyone (`character::Def::public_claim`: Slayer, Psychopath, Damsel guess, Gossip, Juggler) is offered to every living player whenever its character is on the script or in play (`narrator::day_actions`), within a per-player limit, so every phone looks the same. A non-holder is asked the same questions and announced identically to a failed real use ("X shoots" ... "Nothing happens"); real users (`narrator::day_action_users`: holders with the ability active, including believed, drunk, poisoned) work as before; anyone else, including a holder whose ability is not active, bluffs. Superseded for private visits by the Day actions list below.
- Day actions screen (user, 2026-10-22): one **Day actions** button per living phone opens the same list on every phone (`narrator::day_menu`: every claimable ability on the script or in play, with ability text). Claimable abilities are `character::Def::claim` with `character::Visibility::Public` (announced "{player} {announcement} {targets}") or `Private` (the narrator wakes the player for the whole visit; a non-holder is asked the same and told `info::Message::Nothing`). Targets come first (`Def::day_targets`), picked on the phone's town square with Confirm/Cancel and sent with the action (`narrator::day_action_on`); Cancel sends nothing. Travellers and the Atheist stay holder-only (`claim` is `None`; the Atheist would let anyone end the game). Day deaths show as "Y dies", never the cause.
- Madness is an honour-system self-report (user, 2026-10-22): the storyteller cannot hear the table, so on scripts where an ability `causes_madness` everyone gets "I broke madness" once a day (`narrator::report_madness`, `event::Event::MadnessReported`, storyteller-only); `ctx::Read::broke_madness` / `is_mad_about` count it, so `check_madness` and the Mutant act on it. Everyone gets the same reply (`info::Message::Noted`).

## Conventions

- `scripts/check.sh` needs `wasm-pack`, the `wasm32-unknown-unknown` target and node (Playwright tests in `site/tests`). Write Python helper output as UTF-8 (`PYTHONUTF8=1`) on this machine; cp1252 corrupts non-ASCII text.

- Module-qualified paths: `use crate::player;` then `player::Id`. Types don't repeat the module name (each character is `chef::Def`).
- Tests are `expect-test` transcripts in `tests/`. Update them with `UPDATE_EXPECT=1 cargo test`, then review the diff.
